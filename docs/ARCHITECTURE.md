Dig/Fly/Bounce/Rollout/Ice Ball receive distinct presentation; Seismic Toss hit events start a bounded lift keyed by side/slot and active party index, cleared on replay reset. Only the sprite body is transformed, keeping ground rings, HP bars and collision feedback anchored. Reduced motion retains state cues while removing decorative spatial motion. Existing PMD sheet durations set pose speed against the engine windup; this does not change metadata, backend processes or hit timing, and does not claim new SpAttack sheets where unavailable.

`rt/visuals/textures.js` caches original grass/sand floor art and draws an original water atlas over existing Water projectiles in textured/pixel styles. Four measured bright-core anchors avoid padding jitter. Floors use deterministic reflections from saved arena/team names and cache their variant; failed/undecoded images use the existing procedural floor/projectiles. Asset sources, conversion and inspiration are documented in `visuals/PROVENANCE.md`; `scripts/build_rt_visual_textures.py` rebuilds embedded WebP data for both app and standalone builds. No reactive terrain, destruction, new battle rules or save-schema changes are involved. This presentation belongs to the standard singles/doubles arena renderer; the separate mass renderer retains its existing effects.

## Individual competitive set filling

Each TeamBuilder member has its own SmogonSets picker, labelled **Smogon sets** / **Sets de Smogon**. It reads the existing sets_popular handler through the same API/MCP surface and applies setToMember() to that member's draft only. The conversion completes missing EVs with zero and IVs with 31 so an older spread does not leak into the selected set. Saving still goes through the ordinary trainer save; no other member is replaced and opening the picker alone changes nothing. SampleTeam remains a separate roster-replacement action. This clarification adds no bulk fill, backend tool or data migration.

## Suggested replay positions and ability activations

`practice-suggestions.mjs` walks committed replay choices once, clones each selected decision, clears both pending choices and asks `chooseFor` with hidden information and an opt-in complete option trace. Canonical move names are resolved against the request's numbered slots; doubles retain targets. Only comparable decisions with a sufficient heuristic score gap are suggested. Belief/trace failures are skipped, never exposed as hidden-information analysis. Turn pages have a continuation cursor; Python launches a separate engine job so live battles remain responsive. `practice_suggestions` is shared by UI/REST/MCP. Accepting reuses `battle_practice`/`exercise_create`, dismissing is local UI state, and no result/schema migration is needed.

`ability-events.mjs` extracts public classic activation messages and real-time `ability` events, attributes source tags to the correct Pokémon and deduplicates related messages. It excludes silent assignment, move-based ability changes, suppression and items. The classic player adds a separate notification stream beside damage animations; rebuilding/skipping clears it. The real-time screen consumes events only while running, excluding old events on resume. `AbilityBanner` queues each side independently, supports reduced motion and shares ES/EN labels and ability names with exported playable pages. `battle_abilities` uses the same extractor; real time replays only through the saved tick in a separate job, without writing a result.

Rules v6 use the generation dex's `flags.breakable` for Mold Breaker/Teravolt/Turboblaze on defensive immunities, damage modifiers, Sturdy/Disguise and status immunity. Shadow Shield and Prism Armor remain unbreakable. Electric absorption includes Thunder Wave, Magic Bounce reflection is marked to prevent recursive re-reflection, and Mist no longer emits a false ability. Entry weather/terrain/Intimidate, absorption, contact, status immunity, Natural Cure and ability-driven healing/boosting emit named public events; this is not a claim that every classic ability is implemented in real time. New event identity is captured at emission (including doubles slot); legacy events resolve the active party slot from preceding switch events. Versions 1–5 retain previous effects/event streams.

## Portable training exercises

`training.py` reconstructs an engine `practice_snapshot`, stores only its committed input prefix and canonical teams/format, then creates ordinary `kind=practice` attempts. `practice.mjs` returns the canonical prefix alongside its deep snapshot; future decisions never enter the package. V7 adds only `exercises`; attempt metadata lives in existing battle replay JSON and never attaches trainer/challenge IDs. Goal evaluation uses completed turns from the saved position. A three-attempt streak at the latest completed attempt's level suggests one step between random and expert; manual play remains independent of this rule. `exercise_get` explains level, sample count and outcomes.

Six typed tools share UI/REST/MCP handlers: `exercises_list`, `exercise_create/get/start/export/archive`. Generic import recognizes schema1 exercise JSON before the existing sharing parser; engine reconstruction validates it before writing, ignoring noncanonical format/team metadata. Export uses `.silverexercise` through the existing export route. The Share page owns the exercise library and existing replay controls own creation and attempt progress. No new simulator, text model or GPU dependency is added.

## Optional real-time special

Real-time rules version 11 makes the invented Silver special opt-in. `rt_silver_special` defaults to false in Settings (UI/API/MCP). New battles, batch jobs, cups and playable-page exports capture `silver_special`; they never reconstruct a saved choice from current Settings. The simulator ignores the optional flag for versions 1–10, preserving their original behavior and view shape; versions 5–10 keep the special. Version 11 omits its gauge and action when disabled, independently of Mega Evolution. Standalone results carry the boolean alongside their rules version, and import validates and replays it before saving. This changes the extra attack only, not charge-up moves from the Pokémon's four-move set.

## Replay practice

New played and individually watched classic battles retain the simulator's `input_log` in the existing `replay` JSON field when they finish. `practice.mjs` replays only the committed prefix before the chosen turn and clears pending choices, then returns a deep snapshot. `battle_practice` creates a separate live battle from it with a human seat, a hidden-information AI opponent and source/turn/side metadata. Practice-only per-decision AI seeds survive snapshot reloads. Trainer IDs and challenge run IDs are not attached to the branch, so practice cannot award badges or alter trainer records. `battle_compare` reads both results without changing either.

The existing replay page exposes the turn/side controls, original link and final result comparison. Old battles without records, imported results, series/tournament samples and real time remain viewable but cannot open this kind of practice. The new operations use the same handlers for UI, REST and MCP; no alternate simulator or LLM is involved.

The generic `Services.import_any` dispatcher recognizes exercise JSON from strings, bytes and bytearrays. Uploaded `.silverexercise` files therefore reach the same `training.import_` path as pasted text, including UTF-8 BOM decoding through `json.loads`; the Unbound save check still runs first. Tests export a real exercise, upload the file and start a separate practice without changing its source battle.

## Engine (`engine/src`, ES modules, also bundled into the playable page)

- `core.mjs` — formats (`buildFormatId` adds Showdown custom rules after `@@@`), team import/export (`@pkmn/sets`), `completeSets` (fills ability and Tera type), `applyLevelRules` (fixed level, cap, minimum: applied to the sets because Showdown only applies "Adjust Level" in its validator), validation (`TeamValidator`), random teams (`@pkmn/randoms`, seeded), Pokédex search and learnsets, team summaries.
- `points.mjs` — stat points as in Pokémon Champions (66 per Pokémon, 32 per stat): `evFromSp` / `spFromEv` (HOME's rule: 4 EVs the first point, 8 each more), `evsFromPoints` (limits checked), `pointsFromEvs`, `calcStat`. `teamSummary` adds `points`, `points_total` and `stats` at the set's level; engine command `stat_points`.
- `champions.mjs` — registers Showdown's champions and championsregma mods (generated into `champions/` by `scripts/build_champions.mjs` from the pokemon-showdown npm package, MIT) and their formats on @pkmn/sim's Dex: on the base dex and on each mod's (rules are looked up in the format's own dex), plus a recoil helper the mods expect from Showdown 0.11. `core.completeSets` turns a set's EVs into Champions' stat points (`points.championsPoints`: a spread already within 32 / 66 stays); the real-time sim computes Champions stats for those formats.
- `ai.mjs` — `chooseFor(battle, side, {level, style, rng})`. Reads a deep copy of the battle (`freeze` = `JSON.stringify(battle.toJSON())`, `Battle.fromJSON` of a fresh parse; `fromJSON` keeps references into its input, so a copy is never reused). Damage is `battle.actions.getDamage` on the copy (every generation's formula, abilities, items, weather), times accuracy and expected hits, with absorbing abilities handled. Status, setup, hazards, hazard removal, recovery, protection, screens, weather and terrain have their own scores, weighted by style. Switching weighs the best damage given against the best taken. Team preview orders by type matchup. Doubles: per slot with targets, spread moves, ally damage. Expert (singles): up to nine own options × the opponent's three best moves and two best switches, each played out on copies with two seeds, scored by an evaluation (HP, status, boosts, hazards, screens, KO), choosing 0.65 × weighted mean + 0.35 × worst case. Expert (doubles): each slot's three best moves (every target counts) and best switch, paired without sending one bench Pokémon twice or using two gimmicks, the twelve best pairings × the opponent's best pairing and the two with one slot on its second idea, same playouts and score, within 2.5 s. A playout chooses for the opponent first and then for the AI, so a choice a person already sent is replaced by the guess and never read. Revival Blessing's switch request is answered with a fainted Pokémon. With `trace` (an object), `chooseFor` also says why (`fillTrace`, on a copy, after choosing: the same choice and the same random numbers): each slot's ranked options with expected damage, KO and accuracy (a switch's damage taken and dealt), the threat on the slot, who is faster and, for the expert, every candidate turn played out with its mean and worst result.
- `belief.mjs` — an AI that does not see the opponent's team (`chooseFor` with `hidden`). `revealed` reads the battle log's public lines (the public half of each `|split|` pair): `|poke|` (team preview), switches and forme changes (species), `|move|` without `[from]`, `-item`/`-enditem` (not from Trick and the like), `-ability`, `[from] item:`/`[from] ability:` (owned by `[of]` when given), `-terastallize`, `-mega`. `believe` returns a copy of the battle where each of the opponent's Pokémon keeps what was shown and guesses the rest: moves from the app's `beliefs` (usage statistics) or the strongest plain attacks of its types from its learnset, base forme's and pre-evolutions' (no recharge, charge, self-KO or situational moves), item and ability from the beliefs (no item and the first ability without them), Tera type, and stats from the most used spread (even 84 EVs without one) keeping the HP share; the opponent's pending request is rebuilt with the guessed moves. The search and the notes then run on that copy (`trace.hidden`); the expert never guesses a switch to a Pokémon it has not seen (`unseen`, formats without team preview). Services: `_beliefs` (top moves, item, ability, Tera type and spread per species from `smogon.py`), the seat option `ai_hidden` and the setting `ai_hidden_info`; `match_advice` for a person always uses it.
- `replay.mjs` — `replayCheck`: a friend's turn-based battle played again from the page's record (`battle.inputLog`: `>start` with format and seed, `>player` lines with packed teams, every committed choice). The teams must be `prepareTeam` of the expected sets with the challenge's level rules, every choice legal (a `>p2` line pending at the same moment as the `>p1` before it goes first, as the page's AI chose first), forced endings refused, a forfeit applied at the end, a tie after `MAX_TURNS_DEFAULT`. With `ai`, each of the AI's decisions is asked again (`chooseFor`, the page's random numbers `makeRng(rng_id + ':p2')`, the master played as the expert like the page does) and the normalised choice compared: `ai_mismatches`.
- `master.mjs` — the master level (Node only; `ai.mjs` gets it through `setMasterSearch`, so the playable page never loads it). `masterState` turns the live battle into poke-engine's state from the choosing side (both teams with stored stats, HP, status with sleep and Rest turns, boosts, the volatiles poke-engine knows, Perish counts, Protosynthesis/Quark Drive stats, substitute HP, hazards, screens, Tailwind, toxic counter, wish, weather, terrain and Trick Room with their turns, the request's disabled moves for Choice lock, Encore, Taunt and Disable, `switch:`/`move:` last move for Fake Out). `runMaster` runs `silvers_hoard/master_ai.py` with `spawnSync` (state and budget as JSON on stdin; 900 ms of MCTS on up to four threads) and `masterChoice` maps its options (move slot with Tera/Mega, team slot) back to legal choices, merges duplicates and keeps the most visited; with `trace` it adds `search` (iterations, each option's share of visits and average score). Only 9th-generation singles; any failure returns null and `chooseInner` plays the turn as the expert (`trace.fallback`).
- `match.mjs` — `Match`: a battle with two seats; AI seats choose in `advance()`, a person's seat waits for `choose()`. `state(view, since)` returns the new lines for a seat (`viewLines` resolves `|split|` blocks), the pending requests annotated for screens (move type, power, category, description; team sprite ids, types, item and ability names) and the result. Turn limit → tie. `snapshot()` for resuming. With `spec.trace` (every classic battle the app starts; not series or tournaments) each AI decision leaves a note (`compactTrace`); `takeNotes()` hands each out once, `match_start` / `match_choose` / `match_forfeit` / `match_log` return the new ones and the app appends them to the battle's `summary.ai_notes` (kept out of `battle_get`, read with `battle_explain`); `match_advice` traces what the expert would do for a person's side without choosing.
- `stats.mjs` — `summarize` (KOs, damage, faints per Pokémon from the log), `playOut`, `series`, `tournament` (bracket with byes, or round robin with points).
- `benchmark.mjs` — `teamBenchmark` / `sharedSeeds`: several team variants against the same rivals with one resolved master seed (returned in the result for replay); per-rival W/L/T, deltas versus the reference, improved/worsened lists, MVP; never writes the hall of fame.
- `calc.mjs` — `damageCalc({attacker, defender, format, moves, attacker_boosts, defender_boosts, attacker_tera, defender_tera, attacker_mega, defender_mega, weather, terrain, screens, defender_hp})`: both Pokémon on a one-on-one battle of the format's generation (switch-in abilities and their weather happen, then the stated field, boosts, Tera and Mega Evolution win; a defender without moves gets Splash), each move prepared as it is used (`ModifyType` / `ModifyMove`: Pixilate, Weather Ball, Tera Blast; the AI's `estimate` does the same through `usedMove`), and `getDamage` over every damage factor of that generation (39× `random(217, 256)` in gen 1–2; 16 modern rolls from gen 3), with and without a critical hit. Multi-hit moves keep per-strike rolls and combine them with the simulator's hit counts (2–5 weights, Skill Link, Loaded Dice; independent rolls per strike, including Triple Kick power steps): `hits_min`/`hits_max`, min/max totals, `ohko_chance` / `roll_space`. Engine command `damage_calc`, tool `damage_calc` (agent_tools.py calls the engine directly), panel `client/src/components/DamageCalc.jsx` at the foot of the team builder.
- `server.mjs` — the line protocol (one JSON request per line, one answer per line, errors as data). `cli.mjs` — one-shot runs with progress on stderr.
- `scripts/build_unbound.mjs <PUSE clone> <CFRU clone>` — `silvers_hoard/presets/unbound.json.gz`: Pokémon Unbound's Battle Frontier special trainers (`gSpecialTowerTrainers` and `gFrontierBrains` of Complete Fire Red Upgrade's `battle_frontier_trainers.c`: name, class, gender, the four pools) with every set of `frontier_special_trainer_spreads.h` re-derived (species constants to Showdown names, `_A`/`_G`/`_H` forms, nature, IVs, EVs, item, moves) and the ability of its slot as Unbound has it (PUSE's `speciesConstants.json` + `speciesAbilitiesMeta.json` + the ROM's ability table, whose index is one ahead and whose names are cut at 12 letters); everything checked against the generation 8 dex (Leech Fang, Unbound's own, is dropped). Each pool is a team with `pool` (the first six reordered to be different species) in `gen8customgame`, game card `unbound` (gen 8, side). `services.characters()` appends it to `characters.json.gz` at load time, so Palmer, Cynthia, Red, Candice and Giovanni gain these teams under their key; a variant's `credit` replaces the Bulbapedia note on installed trainers.
- `scripts/build_canon.mjs` — parses pret's trainer data (Emerald and FireRed C sources, Crystal asm) into `silvers_hoard/presets/canon.json`: 79 trainers and 4 leagues; empty move slots get the last four level-up moves from Showdown's learnsets, like the games. `scripts/build_names_es.py` — Spanish names from PokeAPI's CSVs into `client/src/battle/names-es.js`. `scripts/build_characters.mjs` — turns `scripts/characters/bulbapedia_parties.json.gz` (Bulbapedia's `{{Party}}` / `{{Pokémon}}` templates of 155 character pages, read from each page's raw wikitext in a browser, since the site refuses scripted clients) into `silvers_hoard/presets/characters.json.gz`: 215 entries (214 shown), 1,821 teams, with `bulbapedia_parties_2.json.gz` (Frontier Brains, villains' admins, more rivals) and `bulbapedia_facility8.json.gz` (`{{lop/facility8}}` rows of the remakes' Battle Tower Master Class, which give stats instead of natures and EVs: the build finds the nature, EVs and IVs that give exactly those stats at level 50), `bulbapedia_facilities.json.gz` (`{{lop/facility}}` rows: battle facility teams with EVs and natures; pools of more than six keep `pool`). Each team has its game cards (`games`: a team of several games is in each) and a role (`category`: leaders, elite, champions, trials, rivals, villains, facilities, tournaments, others) from its class, its battle labels and the character. Every species, move, item, ability and nature goes through the dex of the team's generation (unknown ones are dropped and counted); levels with modes or ranges keep the normal one; tag battles keep the character's side; identical teams of one game merge their labels; rivals' teams per starter are told apart by the Pokémon only that team has; sentences about bag items (potions and the like) leave the note, since battles use held items only; each team gets the Showdown sprite of its game (`-gen1rb`, `-gen2`, `-lgpe`…); Spanish names and battle labels come from `scripts/characters/names_es.json` and `labels_es.json`.

## App (`silvers_hoard`)

- `engine.py` — starts and talks to the Node process (ids, timeouts, restart after a crash), and runs `cli.mjs` jobs with progress and cancel.
- `store.py` — SQLite (migrations V1-V3; V3 adds `badge_image` to gyms and earned badges): `trainers`, `gyms`, `leagues` (with trash), `battles` (seats with their teams, status live/running/ended/failed, omniscient log, summary, snapshot), `runs` (gym and league challenges and their stages), `badges`, `hall`, `jobs`.
- `services.py` — everything: trainers (create, update, random, duplicate, lines with the family's model), canon install (trainers, gyms with badges and level caps, leagues), characters (`characters_list`, `character_get`, `character_install`: a trainer from one team and one sprite, `canon_key` `char:<key>:<team>:<sprite>` so the same pick returns the same trainer, or an own team with `custom`), battles (play, hot-seat, watched; `since` counts lines of the live log; finishing stores the omniscient log, records wins and advances the challenge), challenges (stages, auto mode, badges, hall of fame, optional modern rules), series, tournaments and team benchmarks (jobs; sample battles stored; benchmarks never touch the hall of fame), sharing (files, codes, playable pages, result codes), avatars (pixel art, upload, Prospero job through Hoard Hub), settings.
- `names_i18n.py` — the names the app made up, in both languages: `annotate()` walks what `/api/ui/call` and `/api/overview` return and adds `i18n` {es, en} to trainers (character, cartridge, random), battle seats (also facility rivals with no saved trainer), facility streak stages, gyms and leagues of the games (installed or from the catalog, with their members), challenges, badges and ready-made mass battles, and `region` / `game_id` to gyms, leagues and facilities for the filters. Only text that is exactly what the app would make is annotated, so whatever the user typed stays as typed; a failure never breaks a response. The client reads it with `loc(obj, lang, field)` (`client/src/loc.js`, with `seatNames`, `winnerName` and `battleTitle` for battles); `protocol.renameLine` makes the log's `|player|` and `|win|` lines say the shown names.
- `sharing.py` — wrappers `silvers-hoard/<kind>`, codes `SILVER1-` / `SILVERWIN1-` (zlib + base64url, inflated with a cap), `SILVERWIN2-` (a result with real-time battles) and its input log (`encode_rt_inputs` / `decode_rt_inputs`: nine integers per row, ticks as deltas, the axes in thousandths, deflated, checked on decoding), `FRIEND_MODES`, `parse_any` (codes, JSON files, playable pages, Showdown text), the playable page writer (fills the `silver-data` script tag).
- Optional result team text (`PlayApp`, `Compartir`, `services.py`): every attempt starts with `team_paste` omitted; the result checkbox includes the Showdown copy and displays the actual compressed-code length. The replay's structured team always travels. The date stays fixed while toggling, and cancelled compression cannot replace a newer code. `import_any` reconstructs canonical text from `team` when the optional text was included and returns `team_paste` / `team_format`; the client copies it or calls `trainer_create` only after an explicit save. `_result_fingerprint` excludes presentation text and the log; `_check_new_result` also checks the original, empty-text and canonical-text legacy fingerprints, preserving existing records without a migration. Old unchecked result codes retain their previous verification status.
- `unbound_save.py` — reads the party of a Pokémon Unbound 2.1 save (layout after PUSE, MIT): the newest of the two copies of the game by save counter with every section footer and checksum checked, section 1's party records (unencrypted CFRU layout), ids turned into Showdown names with `presets/unbound_save.json.gz` (built by `scripts/build_unbound_save.mjs`, which matches the ROM's cut names to Showdown's); `import_any` sends any 128 KB flash save there.
- Real time on the friends' pages (`services.py`): `export(..., friend_mode)` (choose / turns / realtime) puts `mode` and `rt` in the page data (`_rt_page_info`: the singles format the arena plays, arena, time limit, rules version, and a key per opponent = fingerprint of its team, AI, that format and the level rules). `import_result` hands any result with a `rt` stage to `_import_rt_result`: it checks the code is coherent (stages in the gym's order, none after a lost one, `won` equal to what the stages say), the friend's team against the gym's rules, and for every real-time stage the opponent's key (a gym edited after the export is a conflict, not a forgery), then builds the spec itself from its own trainer (seed, arena, time limit and rules version come from the code; teams, AI, format and level rules do not) and replays it with `rt_replay`; the replay's winner must equal the stage's `won`. Only then are the real-time battles stored (kind `friend`, mode `realtime`, with the replay so the app can watch it) and the badge or the trainer's record written. Turn-based stages in the same result are trusted as before. A gym page lists its trainers in the gym's own order (`_gym_trainers`).
- `pvp.py` — live battles with a friend on another computer: `Pvp` keeps the rooms in memory (`Room`: a key for the friend's link and one for the host's screen, status waiting → ready → live → ended, the friend's name and team), starts the room server on demand (uvicorn in a thread, 0.0.0.0:`pvp_port`, or `SILVER_PVP_HOST`), turns a room into a battle whose second seat is `remote` (`_host_view` gives this app's screen the first seat's view only; `battle_choose`/`battle_forfeit` refuse the remote side unless they come through the room) and relays real-time frames: every frame of both seats is kept, a (re)connecting screen gets them all, a tick is sent once, hashes every 60 ticks flag a desync. `pvp_server.py` is the room server's FastAPI app: the playable page in room mode (`/r/<id>?k=`), state, join, choose, forfeit and the WebSocket — nothing else of the app. Client: `battle/rt/netplay.js` (`NetLink`, frames, `battleHash`), RtScreen's `net` prop (lockstep: local input read `delay` ticks ahead, a tick runs when both frames are in, no pause), `pages/LiveRoom.jsx`, `play/RoomApp.jsx`.
- `friends.py` — the friends' league (`league`: friend_results grouped per friend and gym or trainer, best result each, points 3 / +1 checked / 1 per battle won / +1 weekly, monthly seasons; `league_export` writes a page to exports and emits `silver.friends.league` on the family bus) and the week's vote (polls and the rule of each week in `data/friends.json`; the vote page `/v/<id>?k=` lives on the room server; `poll_close` sets `week_rules[week]`, which `weekly_info` hands to the page and `_check_week_rule` enforces when a result comes back; only team-building rules, so replays are unaffected).
- `sprites.py` — the sprite cache (download once, remember 404s for a week, fallback to gen 5 pixel art), avatars and the photo → sprite filter (corner flood-fill background removal, crop, premultiplied box downscale, light unsharp mask, 32-colour palette from the visible pixels, outline).

## Move effects on the turn-based screen (`client/src/battle/fx`, `scripts/gen_move_fx.mjs`)

Every move animates on the classic screen with the painter of the real-time mode (`rt/vfx.js`, drawing only), through a thin adapter instead of copied effect code.

- `protocol.js` adds the cues: the `move` cue carries the move id, spread targets and `[still]`; the `-damage` cue carries the move that caused the hit (empty for poison, weather or recoil, with `source` instead), a critical hit and how effective it was (`state.fx` remembers them until the turn ends).
- `fx/move-data.js` is generated (`node scripts/gen_move_fx.mjs`; `--check` and `engine/test/move-fx.test.mjs` fail when it drifts) from the real-time rules' `rtMove`: per move its type and shape (strike, dash, shot, beam, wave, cone, burst, drop, self, field, whole field) so a move looks alike in both modes, without shipping the simulator to the app.
- `fx/plan.js` (pure, tested) turns a move, the positions of the user and targets and a miss flag into a timeline of painter events, projectile flights and hit bursts; `fitTiming` squeezes it into the pause the line gets (about 80% of it) and skips the move's own effect below a 260 ms pause (the 4x speed), keeping the hit burst.
- `fx/stage.js` (`FxStage`, loaded with a dynamic import by `Arena.jsx`, inlined into the single file of the playable page) lays two canvases over the arena (ground marks under the Pokémon, everything else over them, DPR-aware, no pointer events), reads sprite positions from the DOM (`data-fx-pos` on each sprite: side + slot, so doubles work), runs its own clock, and exposes `cue(anim, {budgetMs, speedMs})`, `sync({weather, mons})` (weather particles and status particles while they last), `clear()` and `destroy()`. A new cue replaces what is still travelling, so effects never pile up. Screen shake moves the arena element a few pixels. A striking move also tells the sprite to lunge at its target (`anim.lunge`).
- `player.js` calls `attachFx(stage)`'s `cue` as it applies each line (never when skipping or seeking, which `clear()` the stage) and holds the line for at least the time the effect needs, so the damage shows after the move lands.
- `fx/setting.js`: the "Animaciones de movimientos" switch (`silver-move-fx` in localStorage through `useStored`, in Settings and on the arena) and `prefers-reduced-motion`, which turns the layer off and leaves the sprites' simple animations.

## Real time (`engine/src/realtime`, `client/src/battle/rt`, `silvers_hoard/pmd.py`)

- `za-data.mjs` — Legends: Z-A's base cooldowns of its 337 moves (Serebii, Bulbapedia), its power changes for fast and multi-hit moves, hits per use, and the Speed rule's constants.
- `moves.mjs` — `rtMove(id, gen)`: a move as real time uses it: base cooldown (Z-A's, else `derivedCooldown` from PP, power and kind, mean error 1.3 s against Z-A's table), `finalCooldown` (3 s off per 100 Speed over 25, floor 3 s, priority 3 s), wind-up ticks, shape (`strike`, `dash`, `shot`, `beam`, `wave`, `cone`, `burst`, `drop`, `self`, `field`), reach and the effects the simulator applies. `cooldownTable` for screens and tools.
- `team.mjs` — format id, generation and sets for real time without core.mjs's random-team generator (keeps the browser chunk smaller).
- Data in the browser: real time reads `Dex` (species, moves, items, abilities, natures, the type chart, `Dex.formats` for the generation and game type) and `toID` from `@pkmn/sim`, and `makeRng` from `ai.mjs` (tree-shaken to that function). `@pkmn/sim`'s `dex.mjs` statically imports every generation's learnsets, the event legality tables, the Pokémon GO data and the English descriptions, which only the team validator and the `desc` / `shortDesc` fields use. `engine/scripts/rt_lite.mjs` lists those modules (`RT_LITE_STUBS`) and `rtLitePlugin` in `vite.config.js` replaces them with empty tables in the app build; the build fails if any chunk other than `CombateRt` bundles `@pkmn/sim`, so no screen that needs learnsets or descriptions gets the stubbed copy. The real-time chunk is 1.97 MB minified, 0.43 MB gzip (6.50 MB and 1.03 MB with the full data). The Node engine and the playable page keep the full `@pkmn/sim`. `engine/test/rt-lite.test.mjs` loads the same stubs in a child process (`fixtures/rt-lite-register.mjs`, Node module hooks) and checks against the full one, through `fixtures/rt-lite-runner.mjs`: every species, move, item, ability, nature and type of generations 1-9 (all fields but the descriptions, in `all()` order, which Metronome draws from), every `rtMove` profile, the type chart, every format's `rtFormatId` / `rtGen`, and AI-vs-AI battles in every generation (singles and doubles, rules versions 1-3, Megas, Metronome) plus the recorded v1 and v2 replays: same summaries, lengths, event digests and screen teams. The move profile has no description field, so Node and the browser build the same profile.
- `sim.mjs` — `RtBattle`: 30 ticks per second, a 28 × 17 m arena, one Pokémon per side (two in doubles, see below). Each tick every seat gives an input `{mx, my, use, dodge, sw, focus, plus, mega}` (`ctl`, `tgt` in doubles) (people from the screen, AI seats from `brain.mjs`, which always focuses); acts are `approach` (walk into range), `windup`, `dash`, `roll` (invulnerable), `recover` (after recharge moves) and `switch`. Damage is the turn-based formula with abilities and items; one-stage timed boosts, timed statuses, residual effects every 4 s, weather, terrain, screens, hazards, protection, substitutes, pivots and forced switches. `view()` is what the screen draws; `summary()` has the classic summary's shape plus `mode`, `seconds` and `reason`; `eventLines` writes the stored English log. `rtRun(spec, {inputs, forfeit, tick})` and `fastForward` replay. Determinism: seeded generators (`makeRng`), fixed ticks, `Math.sqrt` instead of `Math.hypot`, no trigonometry, a person's input applied as the log stores it (rounded); Node and Chrome give identical summaries.
  - Rules versions: `spec.version` 1 (missing) is the first rules; 2 adds free aim, the gauge, Plus moves and Mega Evolution; 3 plays doubles formats with two Pokémon per trainer and singles exactly as 2; 4 (what the app stores for new battles) is 3 without Plus moves (`this.plusMoves` false: `plusFor` never arms one, `plusReady` and the view's `plus_ready` are false, a Mega Evolved Pokémon's moves are ordinary; the view carries `plus_moves` and the screen hides the Plus button, keys and help). Input log rows are `[tick, side, mx, my, move, roll, switch, focus, plus, mega]`; seven-column rows from before read as focus 1, plus 0, mega 0. `engine/test/fixtures/rt-legacy-v1.json` holds battles recorded with the first rules and the tests replay them to the same events.
  - Focus: `focus` keeps the Pokémon facing the foe (strafing; moves aim at it; out of range, `approach` first). Without it the facing follows the walking direction; at wind-up the move snaps to the foe within 30° (cos ≥ √3/2), otherwise it goes along the facing: projectiles and beams fly that way, cones and strikes use the facing (a strike lunges 0.6 m), dashes charge that way, drops land at the foe's distance along it.
  - Arena: `spec.arena` `open` (missing) or `rocks`: `placeRocks(seed)` (its own generator, `seed:arena`) gives 3-6 circles mirrored left to right, at least 2.3 m apart, from the walls and from the centre band. `moveBy` pushes Pokémon out of them; projectiles end on them (`fizzle` with `rock`); cones need a clear line; bursts and drops ignore them. `rockOnLine` and `steer` serve the approach walk and the AI.
  - Gauge (version 2): integer units, 3600 per segment, +8 per tick (15 s a segment), +1440 × damage / target's max HP, −15 per tick while Mega Evolved (8 s a segment). `plusFor` spends a segment when a move starts with `plus` (always Plus while Mega). Plus: damage ×1.2 (×1.3 super effective), secondary chances ×1.67 (≤ 100), heals ×4/3, cone and burst reach and drop radius ×1.2, protection pierced for 25% (`protected` with `pierced`); event `plus`. ## Cups (`silvers_hoard/cups.py`, `client/src/pages/Copa.jsx`)

- A cup is one row of `cups` (schema 5): its spec (format, mode, best of, arena, AI level, pace), the entrants and the bracket as rounds of matches. `build_rounds` lays out 2^k places with the usual seeding (`seed_order`: 1 meets the last, the top seeds get the byes) and plays the byes at once; `_decide` sends a winner to its place in the next round.
- A match is `wait` (a place still empty), `ready`, `sim` (the AI is playing it), `live` (a battle is being played or watched) or `done`. A background thread per cup (`advance` / `_loop`) plays the AI's ready matches one at a time, a game per engine job (`tournament` with two entrants and best of 1), storing each game as a battle (`kind` cup, `run_id` the cup id) and the score as it goes; ties do not count, and after 12 games the better score or a coin decides. `pace` keeps at least that many seconds between matches so the bracket can be followed.
- The person's matches wait: `play` starts a battle of the human trainer against the rival (`battle_start` with `run_id` the cup), `simulate_mine` / `simulate_match` hand a match to the AI, `watch` turns an AI match into a watched battle. `Services._after_end` sends any ended battle whose `run_id` starts with `cup_` to `on_battle_end`, which counts the game and closes the match or leaves it ready for the next game. `recover` (at start) puts matches left `sim` back to ready and drops games whose battle did not survive; `stopped` stops the threads when the app closes.
- The page polls `cup_get` and animates what changed since the last poll (a match that just ended, the winner entering the next round); the bracket is laid out with computed positions and one SVG of connectors.

## Neural AI (`engine/src/neural.mjs`, `scripts/neural_ai_server.py`, `silvers_hoard/neural.py`)

- The level `neural` asks a reinforcement-learning policy (metamon's pretrained Kakuna by default) served on the GPU by `scripts/neural_ai_server.py`, which runs in its own Python environment (PyTorch, metamon, amago) and never imports the app. Without flash-attn it replaces `FlashAttention.forward` with a plain-PyTorch causal sliding-window attention over the same key/value cache (no parameters, so the same weights load) and runs eagerly (`TORCHDYNAMO_DISABLE`, no Triton needed).
- Per decision the engine (`neuralChoice`, registered in `ai.mjs` with `setNeuralSearch` when `SILVER_NEURAL_URL` is set) posts the battle's lines as that side saw them since its last decision (`viewLines` of `battle.log`) plus the side's request; a short Node child does the HTTP call so the AI stays synchronous. The server keeps one session per battle and side (metamon's battle object fed with the protocol, the observation space, the transformer's cache, at most 8, forgotten after 30 minutes) and answers with a choice by request slot; a repeated request id gets the same answer. Singles of generations 1-4 and 9 only; anything else, or a failed call (the session is then started over from the first line), falls back to the expert and the trace says so (`neural`, `neural_error`, `fallback`).
- `NeuralAI` in the app starts the server (`neural_ai_python`, `neural_ai_model`, `neural_ai_gpu` as an nvidia-smi index with `CUDA_DEVICE_ORDER=PCI_BUS_ID`, `neural_ai_port`, weights in `data/cache/neural`), starts it in the background when a seat with that level is made, reports `/health`, and stops it when the app closes. `engine/test/fixtures/fake-neural-server.mjs` stands in for it in tests.

## Arenas and gym maps (`silvers_hoard/arenas.py`, `silvers_hoard/gymmap.py`, `client/src/pages/Arenas.jsx`, `client/src/pages/GymMap.jsx`, `client/src/battle/overworld`)

## Data formats

- `.hoardtrainer` `{kind: "silvers-hoard/trainer", schema: 1, app, owner, exported_at, trainer: {name, title, owner, format, team, ai, dialogue, notes, avatar: {kind: showdown|image}, source_id}}`; `.hoardgym` has `gym: {…, badge_image: {kind: shape, shape} | {kind: image, mime, data}, leader, trainers}`; `.hoardleague` `league: {…, gyms, elite_four, champion}`.
- Result codes: `{kind, gym_id | trainer_id, gym_name | trainer_name, challenger, won, turns, date, team, team_paste, stages, log?}`. A turn-based stage carries `input` (the input log), `rng` (the AI's random-number key, the match id) and `forfeit`, and the code `ai_version` (`services.ai_version()`: sha1 of ai/belief/match/core.mjs and the simulator's package.json; the page gets it in its data) and `v: 3`. The import replays each stage before recording anything; with the same AI version a differing AI choice rejects the code, with another version only the rules are checked (`proof.ai_checked`). Every replayed stage is stored as a battle (`summary.replayed`), and `proof.verified` puts "checked by replaying its battles" on the badge. Every imported result (both paths) adds a row to `friend_results` (schema V4: target, challenger, won, battles and battles won, turns, `hp_left` from the replay, verified, week, mode, battle and badge ids, and the code's `fingerprint`, so the same code is refused the second time with 409). `leaderboard(kind, target_id, week)` groups them per gym or trainer and keeps each friend's best (key: won, verified, battles won, fewer turns, more HP left, earlier); `leaderboard_remove` deletes rows only. The week's challenge: `export(..., weekly=True)` (pages only, turns only) puts `weekly: {week, seed}` in the page data (`weekly_info`: ISO week, seed = sha1 of kind, id and week); the page creates battle i as `Match({id: seed-i, seed: seed-i})`, so the battle's seed and the AI's random numbers are the week's, and the code carries `weekly: week`; the import replays each stage with `expect_seed` (`replay.mjs` compares the `>start` seed with `seedArray(expect_seed)` and the AI key with it) and refuses real-time stages or stages without a record. The play bundle is built with `esbuild.keepNames`: `@pkmn/sim`'s State names references by class name, and minified names broke every copy of a battle, so the page's AI used to fall back to default choices.

## Mass battles and played runs (`silvers_hoard/mass.py`, `engine/src/realtime/mass.mjs`)

Rules are versioned in `spec.version` (a spec without one is version 1): 1 caps an area move at eight Pokemon and fires moves around the user at once within 3.4 m; 2 removes the cap and rolls those moves out as a wave (`waves`, `updateWaves`, a `wave` event the screen draws from the battle clock); 3 makes a wave a spread move only when more than one foe is within reach as it starts. `composeMass` writes the current `MASS_VERSION`; saved battles keep theirs, so their fingerprints never change. `MassRenderer` draws moves through the real-time `Vfx` class (`areaAt`, `areaKind`, `meleeAt`, `rayAt`, `hitAt`).

`Mass.compose` builds a roster through `mass-roster.mjs`; `mass_run` runs the same deterministic simulator used by `MassScreen`. Battles support free-for-all, teams and giants against a crowd, with up to 1100 Pokemon. A saved battle is an atomic JSON file in `data/mass`, containing its complete spec, seed, result and final hash. Replays use that snapshot; saving another battle does not prune the library. UI, REST and MCP use the same `mass_*` handlers in `agent_tools.py`.

A controlled run adds `spec.player.unit`, the Pokemon's index across the spec's teams. The screen records changed inputs as `[tick, mx, my, slot, ax, ay, roll]`; directions are thousandths and aim coordinates are centimetres. `mass_play` replays the log in the engine, checks a supplied final hash and appends the run to its battle. `mass_play_get` returns the input log for another replay; `mass_play_delete` removes that run. The saved AI battle's spec and result remain unchanged. `UnitPicker` selects a unit; `MassScreen` shares the controls, rendering and local simulator between the app, the recorder and the friends' page.

`mass_export` fills the packed play template with `kind=mass`, the full snapshot, its reference hash and a short table of played runs. Every export gets a new HTML filename and returns its battle id and hash. `MassPlay` watches or plays the embedded battle without an app server; optional sprites may come from the configured sprite server. It gives a played run back as a `SILVERMASS1-` code with the unit, packed inputs, challenger and final hash. The normal `import` handler replays that code before saving the friend's run; importing the HTML instead creates a separate saved battle from its embedded spec. Exported files do not depend on the original library entry remaining present.

`mass_video` starts a normal video job for the AI battle or a saved played run. The recorder opens the app's `Video` route and reuses `MassScreen`, its automatic camera and the page's audio. It captures a clip through the existing browser recorder and can convert it to MP4 with ffmpeg; without conversion the result is WebM. The job exposes its file and download URL and optionally sends it to the family's video editor. This path uses the running app; the standalone shared HTML is a separate flow.
## Shared trainer picker and replay corrections
