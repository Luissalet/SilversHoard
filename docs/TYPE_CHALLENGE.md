# Type challenge

Facilities includes a ten-question local practice game. Choose Attack or Defend, a generation (1–9), one or two defensive types, and optionally a seed. Attack offers four attacking types against one Pokémon, with exactly one highest multiplier. Defend offers four Pokémon against one attacking type, with exactly one lowest multiplier. It practises type-based switching decisions; abilities and other battle conditions can change a real switch's outcome. After answering, the game shows the factors for each defensive type and your current streak. The result reviews mistakes and records the best streak for that attempt. Repeat reuses the same questions and goal; a new unseeded attempt creates a new seed.

The installed historical Dex supplies species and type charts, including generation-one immunities, later type changes and double weaknesses/resistances. The pool contains canonical base species available in that generation's installed Dex; alternate forms and nonstandard entries are excluded. It is not a National Dex completion game. The multiplier uses only the type chart: no abilities, items, STAB, move power, weather, Terastallization or actual damage calculation.

`type_challenge` accepts `version: 1`, `gen`, `mode: "single" | "dual"`, `goal: "attack" | "defend"` (default Attack) and a nonblank `seed` of at most 100 characters. It returns a specification and ten questions, without answers. Attack retains its existing seeded questions, choice order and canonical specification, which omits `goal` even when Attack was requested explicitly. Defend includes `goal: "defend"` in its specification and uses a separate seeded stream. Its questions have `{round, attack, options: [{species, types}]}`. Ten attacking types are distinct; four defenders are distinct within each question, but may recur in another question. The best defender has the generation/type pool's minimum multiplier; the other three are strictly worse. Types without three eligible alternatives are skipped.

`type_challenge_score` takes that specification plus zero to ten answers in question order: attacking type names for Attack, canonical Pokémon names for Defend. It regenerates the questions, validates each answer against its four choices and returns feedback, correct/answered counts, current/best streaks and completion. Defender feedback includes the species, types, multiplier and individual type factors for the chosen and best options. Supplied question objects are never authoritative. Both are uncapped read-only tools shared by UI, REST and MCP.

The UI supports Spanish and English, keyboard choices, focused question/result headings, reduced motion and narrow screens. A failed request can be retried with the same pending answer or generated seed. There is no timer, account, leaderboard, saved attempt, battle or history entry. The current attempt stays in the mounted Facilities page; navigating away or reloading ends it. This mode is in the local app and is not a portable HTML export. It adds no packages or network providers.

Implementation: `engine/src/type-challenge.mjs`, `TypeChallenge.jsx` and scoped `type-challenge.css`. Verification covers historical factors, both goals across all generations and difficulties, unique answers/species, forged input, partial scoring and unchanged database tables through the native handlers. A fixture captured before the defensive extension checks exact Attack deck and score hashes for 54 generation/mode/seed combinations.
